# Bot 聊天调用已连接应用：需求说明

状态：已实现；2026-10-16 调整连接范围为当前空间全 Bot 共享。原始实现见 [v0.4.4 发布说明](releases/v0.4.4.md)，最新规则见 [v0.4.5 发布说明](releases/v0.4.5.md)。

记录日期：2026-10-15。代码检查基线：`main` / `c7afbd337d36`。

## 1. 用户需求

用户在「应用连接」中连接应用后，当前空间内所有 Bot 的单聊、群聊和任务均可直接使用，无需逐个分配；以后新建的 Bot 也自动可用。用户不需要切换到单独的任务页面，也不需要重新提供 Key 或 Token。

实际反馈：AI 音乐和致用 OctoBus 都已经填写凭据并连接，但在 Bot 聊天中要求使用时，Bot 回复找不到应用或工具。排查确认，这是普通聊天未接入工具执行的共性问题，并非只影响这两个应用。

核心目标：打通「连接应用 → 聊天提出需求 → 调用工具 → 必要时确认 → 展示真实结果」的完整流程。

## 2. 开发前已核实的现状

| 环节 | 当前行为 | 缺口 |
| --- | --- | --- |
| 应用连接 | 校验凭据或发现 MCP 工具，保存连接与 `allowedBots` | 连接成功不等于聊天已获得工具能力 |
| 普通 Bot 聊天 | `/api/chat` 直接调用模型并保存文字回复 | 未加载已授权工具，也未执行模型返回的工具调用 |
| Bot 群聊 | 各 Bot 直接调用模型生成回复 | 同样未接入工具执行 |
| 任务流程 | 已有工具目录、执行循环、操作确认和执行记录 | 未接入聊天；公司空间缺少可进入的任务入口 |

代码定位：

- `backend/internal/api/chat.go`：普通聊天的 `SendMessage`。
- `backend/internal/group/orchestrator.go`：群聊调用模型的流程。
- `backend/internal/agent/service.go`：任务执行调用 `Tools.Loop`。
- `backend/internal/connectors/runtime.go`：工具目录、执行循环、确认与恢复基础。
- `backend/internal/enterprise/workspace.go`：公司空间已创建连接器并绑定到 Agent 服务。
- `frontend/src/components/ConnectionsPanel.tsx`：连接管理及 Bot 授权。
- `frontend/src/components/TaskExecution.tsx`：现有执行记录和操作确认界面。

以上结论来自代码检查及现有自动化测试，不等于所有真实外部应用都已完成端到端联调。

## 3. 应用与空间范围

本次应统一覆盖现有连接器，不为音乐或 OctoBus 单独写聊天特例：

| 应用 | 接入形式 | 范围说明 |
| --- | --- | --- |
| AI 音乐、AI 生图、视频 API、云浏览器、设计提示词 | 内置 API 连接器 | 使用已实现的工具能力与既有操作确认规则 |
| 致用 OctoBus、Agent 工具包、自定义 MCP | MCP 工具发现与调用 | 使用该连接实际提供、当前用户在该空间连接的工具 |
| Notion | 内置 API 连接器 | 仅访问该凭据已获授权的页面与动作 |
| Gmail | OAuth 连接器 | 在当前支持的个人空间中接入；不因本需求开放公司空间 Gmail 授权 |

普通单聊是核心验收范围，个人空间和公司空间均需支持。群聊存在相同缺口，列为配套改造范围；若分阶段交付，必须明确标注群聊尚未支持，不能将单聊完成描述为所有入口完成。

不新增上述平台尚未实现的业务能力；不把飞书、钉钉消息渠道接入、定时执行、全自动免确认等能力并入本需求。

## 4. 功能要求

### 4.1 工具发现与授权

- 每轮执行根据当前空间、用户、Bot、连接启用状态和动作权限生成可用工具目录。
- 连接成功后，无需重启客户端或重新连接，即可在下一轮聊天使用。
- 区分「未连接」「连接已停用」「动作被禁用」「连接已失效」等情况，给出可操作的提示。
- 断开连接、停用连接或停用账号后，后续执行立即重新校验；等待确认的旧请求不得继续沿用已失效授权。
- 群聊中每个 Bot 均可使用当前空间的已启用连接；仍需检查发言资格和 Bot 动作策略。其他公司用户及其他空间的凭据不共享。

### 4.2 聊天执行

- 将允许使用的工具及参数结构传给模型，执行合法的工具调用，将结果回传模型，直至得到答复或明确停止。
- 普通问答仍可直接返回，不强制调用外部应用。
- 不能用固定回复、虚构工具结果或仅增加系统提示词替代真实执行。
- 使用现有执行、授权、确认和去重机制；不能为聊天新建一条绕过既有检查的调用路径。
- 明确工具不可用、参数错误、网络超时、模型不支持工具调用等失败原因。没有执行成功的操作不得显示为完成。
- 保持有界的工具轮次、单轮调用数量和执行时间；超过限制给出明确提示，不无限循环。

### 4.3 操作确认与恢复

- 继续遵循既有规则：音乐生成等付费或有副作用的动作需要确认；所有 MCP 调用沿用当前逐次确认要求。
- 在当前聊天内展示操作、使用的应用/账号和关键参数，让用户批准或拒绝；不要求用户到隐藏任务页面处理。
- 批准后继续对应执行；拒绝或取消后停止该操作，不换工具绕过。
- 确认绑定当前用户、Bot、会话、具体工具、参数及有效授权版本；不能跨会话复用批准。
- 刷新、切换 Bot、客户端重连和服务重启后能恢复可理解的执行状态。
- 已成功的外部操作不得因恢复或重试重复执行；结果不明时显示「待核实」，不自动重复付费、发送或创建操作。

### 4.4 聊天展示与成果

- 聊天内可看到使用了哪个应用、由哪个 Bot 执行、当前状态以及成功或失败的结果。
- 等待确认、执行中、失败、取消和结果待核实应清晰区分；长任务不能只留下一个无法解释的等待状态。
- 展示实际产物、链接或可访问的下载入口。公司服务端文件不能只返回一个用户电脑无法访问的 `/data/...` 路径。
- 保持公司用户之间、个人/公司空间之间的凭据与数据隔离；不在消息、日志、错误提示中展示 Key 或 Token。

## 5. 验收标准

| 场景 | 预期结果 |
| --- | --- |
| 音乐已连接，在聊天要求查询自己的音乐任务 | 实际执行查询工具，聊天展示真实结果及调用记录 |
| 要求根据需求生成音乐 | 经过所需方案步骤；付费生成前展示确认；批准后执行，拒绝后不生成 |
| OctoBus 已连接，在聊天要求执行该 Token 实际提供的能力 | 模型获得对应工具；确认后实际调用并显示返回结果 |
| 其余现有连接器 | 每类至少一个真实可用动作验证聊天调用；没有真实凭据时标明尚未联调 |
| 应用连接已停用 | 不下发、不执行该应用工具，并提示启用或重新连接 |
| 应用已连接，但 Bot 动作策略禁用某动作 | 该动作不能执行，也不能通过另一条聊天路径绕过 |
| 执行等待确认时撤销授权或断开连接 | 原确认失效，继续执行被拒绝 |
| 普通问答 | 正常回复，不强制工具调用，不破坏聊天历史和记忆 |
| 多 Bot / 群聊 | 工具记录标明执行者，共享当前空间连接，不访问其他用户/空间的凭据；现有群聊参与和轮次规则不变 |
| 公司用户 A 与 B | 不能读取、批准或执行对方的连接和工具记录，不能下载对方产物 |
| 刷新、重连、重启、重复提交 | 状态可恢复；成功操作不重复执行；未知结果不会自动重试 |
| 工具或模型服务失败 | 显示真实失败原因，不把文字回复当成执行成功 |

真实联调优先从只读操作开始；产生费用或修改外部数据的测试按现有确认流程执行。

## 6. 实施与交付要求

1. 先设计聊天与既有任务执行之间的持久化关联，覆盖工具记录、批准、取消和恢复。不能只把 `Chat` 替换成 `Loop` 而忽略它依赖的任务状态和授权上下文。
2. 实现后端单聊工具执行及前端聊天内的状态、确认、结果展示，再按上述范围处理群聊。
3. 补充端到端测试：从保存连接、新建 Bot、发聊天消息一直到真实连接器执行与结果显示；使用模拟外部服务验证确认、撤权和去重。
4. 同时覆盖个人空间 SQLite 和公司空间 PostgreSQL；保留既有聊天、任务、记忆和空间隔离行为。
5. 验证目标模型的工具调用及多轮工具结果兼容性；当前试用模型为 `deepseek-flash`。普通文本回答成功不能代替这项验收。
6. 提交业务代码 MR、构建企业服务端镜像和最新桌面客户端；部署仓库另提镜像更新 MR。提供真实联调记录，明确已完成和未完成的应用/入口。

仅增加任务入口可作为临时辅助，但不能替代「直接在 Bot 聊天中调用已连接应用」这一核心需求。
