# Mac 与手机的 Bot 聊天同步方案

状态：方案，完整聊天同步尚未实现、部署或完成真机验证。

## 用户体验与数据归属

首版使用 Mac 作为唯一数据源，手机是加密远程客户端。两端使用相同 Bot ID、会话 ID、消息 ID；侧栏每个 Bot 一个入口，默认继续最近的对话。历史会话保留，避免合并、覆盖已有数据。手机不另建一套独立对话库，减少双向合并冲突。

安装手机 App → 扫描 Mac 配对码 → 两端核对确认码 → Mac 允许设备。连接之后读取同一份 Bot、聊天和记忆。模型密钥留在 Mac，由 Mac 调用模型服务；手机不获取模型密钥。

Mac 必须联网并保持唤醒。离线时显示最近同步时间和只读缓存；首版禁用发送，不暗中排队重试。若产品要求 Mac 关机后仍可对话，需要第二阶段常驻云主机或独立执行端，不能仅通过当前中继实现。

## 已有基础与缺口

- `backend/internal/mobile/service.go` 已有配对、设备撤销、加密中继、Bot 请求作用域、写请求摘要和幂等回执。中继部署方式见 `deploy/README.md`。
- `frontend/src/mobile/client.ts` 已有加密请求、设备凭据与重连基础。
- 手机当前可查看 Bot、任务、工具审批、记忆。中继允许列出会话，但尚未允许读取会话详情或发送聊天；`MobileApp.tsx` 尚无聊天页面。
- iOS 下载取决于正式发行链接，远程服务取决于部署配置。安装、配对、聊天同步是三个独立状态，不能把「中继已连接」显示成「聊天已同步」。

## 实施顺序

1. **统一持续对话。** 后端增加按 Bot 查询／原子创建当前会话的接口；两台设备首次发送同时发生时也只建立一个当前会话。既有会话保留在该 Bot 历史中。
2. **补齐移动聊天接口。** 增加明确的会话详情、分页消息读取和异步提交消息接口，并逐条加入移动允许列表。现有中继是有响应大小和超时限制的请求／响应通道，不直接转发长时间 SSE；发送返回操作 ID，由 Mac 执行，手机拉取进度。
3. **消息幂等与排序。** 手机发送稳定的 `clientMessageId`；Mac 对 `(botId, clientMessageId)` 建唯一约束，并在事务中写入消息与执行回执。请求重试返回原结果。以服务端分配的单调序号排序，不以设备时间排序；同一会话串行执行生成操作，两端并发发送按服务端接受顺序排队。
4. **增量刷新。** 按 Bot / 会话提供游标拉取，涵盖新消息、生成状态、编辑版本与删除墓碑；掉线后从确认游标补齐，过期游标返回重新拉取信号。Mac 也使用统一刷新机制，以显示手机发送的消息。
5. **移动 UI 与缓存。** 复用 Bot 列表、消息样式和输入框；显示发送中、已确认、失败、离线及最后同步时间。只读缓存需加密、可清除；撤销设备后禁止继续访问，客户端清理本地缓存。不要承诺能远程删除已经离线的设备副本。
6. **发布联调。** 部署产品所属 HTTPS 中继和移动站点，配置客户端允许的地址；完成 iOS 签名／TestFlight 发布，真机验证后才能标记聊天同步可用。业务内容在两端加密，中继不承担持久备份。

## 验收

- Mac 发消息后手机可看到，手机回复后 Mac 可看到；相同 Bot 的消息一致，切换 Bot 不串记录。
- 两端首次同时发送不会新建两份当前会话；重复请求只保存一次、只启动一次模型调用。
- 生成期间断网、Mac 休眠、客户端重启可准确恢复状态；无法确定的发送结果先查询回执，不自动重复生成。
- 长记录分页、游标补齐、编辑和删除一致；撤销设备立即拒绝新请求。
- 用模拟模型覆盖一致性和故障测试，再用授权测试账号做真机验证；不使用用户的模型额度跑示例任务。
