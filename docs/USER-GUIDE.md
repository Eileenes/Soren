# Soren 0.4.1 使用说明

当前可在 Mac 本地使用，无需登录 Soren 或 GitHub。手机扫码配对、加密中继和 iOS 工程已实现并完成本地验证；公共服务与正式手机分发尚未上线，默认安装包暂不能远程关联手机。当前产品介绍见 [README](../README.md)。

首次打开会出现「开始使用 Soren」引导，依次带你连接模型、设置 Bot、尝试任务和连接应用。随时可跳过，顶部「使用引导」可重新打开；示例任务只填入输入框，由你点击开始执行。

## 1. 安装并配置模型

打开 `release/Soren-0.4.1-macOS-arm64.dmg`，把 Soren 拖入「应用程序」后启动。若旧版正在运行，先从菜单栏选择「退出 Soren」。升级不需要删除 `~/.soren` 数据目录。

进入左侧底部「设置」，找到「模型」：

1. 选择模型服务商，或选择「兼容接口」。
2. 填写服务商提供的「接口地址」和「API Key」，点击「获取模型」，在应用内下拉列表选择模型。不支持列表的接口仍可手动填写模型 ID。
3. 点击「保存模型连接」，等待本地服务重新启动。选择会用于对话及新任务，Bot 单独指定的模型仍优先。
4. 进入「对话」发送一句话，确认收到真实模型回答。

模型必须支持工具调用，才能执行连接器任务。界面仍显示「本地演示」或「未连接模型」时，只能体验界面与数据保存，不能视为真实 AI 已配置成功。API Key 填在设置中，不发到聊天里。配置模型会重启服务，尽量在没有任务运行时修改。

## 2. 先跑通一个最简单的任务

选择左上角的默认 Soren，打开「任务」，输入：

> 帮我制定一份三天学习计划，每天包括目标、行动和检查项。调用本地成果工具，保存为 Markdown，标题叫“三天学习计划”。

点击「开始任务」，展开任务记录。应看到工具执行记录和「本地成果」，可以预览和「下载 Markdown」。Mac 版下载到 `~/.soren/exports`，并在 Finder 显示文件。

此流程只需模型配置，不需要 GitHub 登录，也不需要 Gmail 或 Notion。只有模型声称“已保存”而没有成功工具记录和成果，不算实际保存成功。

## 3. 创建多个 Bot

「侧栏加号 → 创建 Bot」：选择头像、填写名称后创建。模型继承全局配置，协作默认开启，无需选择。进入聊天后，Bot 会先问“我的职责是什么？”，你的第一条回复会直接保存为职责；以后可通过右键「配置 Bot」修改。

可直接使用的职责示例：

> 你是工作助手，负责整理工作资料、拆解行动计划、起草邮件。输出简洁，区分事实与建议；调用已授权工具完成任务，并报告实际结果。

职责决定工作方式，连接权限决定它实际能操作哪些应用。仅在职责里写“会发邮件”不会自动获得邮箱权限。

侧栏顶部可切换当前 Bot。私有记忆和历史按 Bot 隔离；需要共用的内容放入「共享资料」并指定可访问的 Bot。当前协作任务不会直接加载各 Bot 的私有长期记忆，因此任务必要资料应写进目标或放入获准的共享资料。

桌面端可通过侧栏顶部的收起按钮切换为头像导航，点击第一个头像上方的展开按钮恢复列表。右键 Bot 或群聊可配置、置顶、重命名或删除；Bot 的删除会移入「我的 Bot → 已归档」，保留对话和记忆并支持恢复，默认 Soren 不可删除。

## 4. 多 Bot 如何协作

新建 Bot 默认允许协作。切换到发起方，进入「任务」，在「邀请协作」选择成员，填写共同目标并开始。旧版已有的特定协作授权保持原值。

例如：「工作助手整理方案，创作助手改写为适合发布的文案，最终汇总保存为 Markdown。」目前按指定参与者的步骤传递成果，最多邀请 3 个其他 Bot；不是无人值守的无限互聊。参与者只能用自己获得授权的连接。

### 群聊

侧栏加号可创建群聊，只需填写群名、主题并选择 2–5 个成员；右键「配置群聊」可修改这些内容，无需选择模式。

- `@产品 请给我建议`：只由指定 Bot 回复一轮。
- `大家觉得这个方案怎么样？`：全员各回复一次，随后结束。
- `请大家讨论一下这个方案`：成员依次回应彼此，最多三轮；没有补充时可提前结束。
- 讨论中可点击「中止讨论」。结束后会询问是否继续；点击「继续讨论」或回复“继续”才会开始下一批，仍最多三轮。没有用户的新请求，不会自动讨论。

## 5. 连接 Gmail、Notion 或 MCP

进入「应用连接」，选择服务，填入连接资料，并勾选「可使用的 Bot」。创建成功后，连接卡片显示账号和获准 Bot；可用「权限」调整或「断开」撤销。

| 服务 | 需要准备 | 本版能力 |
| --- | --- | --- |
| Gmail | Google 桌面 OAuth 客户端的 Client ID、Client Secret，再到浏览器授权 | 创建纯文本邮件草稿、确认后发送；暂不读收件箱 |
| Notion | 内部集成 Token，并在 Notion 中将相关页面授权给集成 | 搜索、读取页面第一层内容、创建子页面 |
| MCP | 兼容的公网 HTTPS Streamable HTTP 地址，可选 Bearer Token | 发现并调用远程工具；不支持 MCP OAuth 或本地 stdio |

外部平台的凭据准备见 [连接器配置说明](CONNECTORS-DELIVERY.md)。当前是开发预览版，仍需自己准备这些资料；尚未提供普通用户一键连接的托管 OAuth 服务。

连接后，从「任务」交办，例如：

> 使用 Notion 查找我已授权的“项目计划”页面，整理本周行动清单，保存为 Markdown。

> 给【填写真实收件邮箱】创建一封 Gmail 草稿，主题是“本周进展”，正文为【填写内容】，只保存草稿，不发送。

发送邮件或创建 Notion 页面时，展开「待确认」任务，核对账号与完整参数，点击「批准此操作」，再点击「继续任务」。普通「对话」目前不会调用这些工具。出现「结果待核实」时，先到对应服务检查实际结果，避免重新发任务造成重复操作。

## 6. 无需 GitHub 登录

安装后直接配置模型即可使用本地功能，不需要 GitHub 账号、OAuth Client ID，也不用部署 Soren 服务器。设置中已移除早期 GitHub 登录表单。模型服务凭据与 Gmail、Notion 的授权是各自应用的配置，不是 Soren 的账号登录。

外观在「设置 → 外观」选择「浅色」「深色」或「跟随系统」。跟随系统会实时响应 macOS 外观变化；顶部太阳/月亮按钮会切换到手动主题。

## 7. 手机如何关联 Mac

手机通过扫码与 Mac 确认加入同一本地空间，不以同一 GitHub 账号登录为前提。普通用户无需自建服务器，但产品方需要先部署公共连接服务并提供可安装的手机 App。

**当前默认安装包尚未接入公共服务，因此暂不能直接远程关联。** 配对协议、手机任务与记忆入口已完成本地链路和 iOS 模拟器验证；真实手机扫码、正式签名与分发尚待完成。

服务和手机 App 就绪后的操作顺序：

1. 在 Mac 的「设置 → 关联设备」开启连接，等待就绪后生成二维码。
2. 手机打开 Soren，选择「扫描 Mac 二维码」。
3. 核对两端确认码，在 Mac 上批准关联。
4. 手机可选择 Bot、发起任务、查看成果和记忆、批准操作，任务仍由 Mac 执行。
5. 不再使用的手机可从 Mac 关联设备列表撤销。撤销会阻止新访问，但不会自动取消已接受的任务。

Mac 需要保持运行、联网且未休眠。当前配对手机拥有该空间的全部 Bot 任务/记忆访问及审批权限；手机编辑 Bot、完整聊天、推送和离线编辑尚未交付。Android 也尚未交付。

开发者可按 [部署文档](../deploy/README.md) 运行本地中继验证流程；权限、实现和真机验收边界见 [手机联动说明](MOBILE-040-DELIVERY.md)。本地 localhost 示例只适用于开发机或模拟器，不能直接作为真实手机可访问的地址。

## 8. 日常启动和退出

- 关闭窗口：应用留在菜单栏，后端继续运行。
- 重新打开：点菜单栏 Soren →「打开 Soren」。
- 完全退出：菜单栏 Soren →「退出 Soren」。
- Mac 休眠后本地任务不能持续执行；当前没有开机自动启动服务。

下一步最实用的验收顺序：先完成一个本地 Markdown 任务，再连接一个真实 Notion 或 Gmail 账号并完成真实任务，最后按部署指南验证手机联动。
