# Bot 模板链接分享与职责边界方案

状态：模板链接分享、独立模板服务、配置边界编辑与版本恢复已实施。部署与实际交付范围见 [使用和部署文档](bot-template-service.md)。发布者认证首版采用管理员分配的独立凭据，尚未接入 OAuth 登录；本地 Bot 永久清除、组织内受限访问及跨平台实机验收仍为后续工作。以下保留完整规划。

原定方案：用户已选择「导入自己的 Soren 后使用」，分享入口采用「创建 Bot 模板」：将配置发布为链接，接收者打开链接并导入自己的应用。本方案不包含公共网页聊天或 Bot 市场。

前置交付：OAuth 配置已提交为 `05c795c`，目前只支持保存 IdP 参数，尚未实现授权登录、回调、令牌交换和会话。模板链接需要轻量托管服务；发布者登录与模板归属校验需要另行实现，不能将已有 OAuth 配置视为已完成认证。

## 1. 产品目标

作者在 Bot 配置中定义职责、工作方式与权限，点击「创建 Bot 模板」，预览后发布并获得 HTTPS 链接；接收者打开链接，唤起 Soren 后自动显示 Bot 卡片，点击「导入到我的 Soren」后得到独立副本，使用自己的模型、数据和工具账号。

分享的是可复用的角色配置。对话、私人记忆、账号凭据、连接授权和作者本地文件不随配置传播。接收者可编辑、删除自己的副本；作者后续修改或删除原 Bot，不会影响已导入副本。停用链接可以阻止后续从服务下载，不能远程撤回别人已经取得的配置或副本。

模板服务只存储和分发配置、版本及来源信息；Bot 对话和工具执行仍在接收者自己的 Soren 中进行，使用接收者的模型与工具额度。JSON 是底层格式，手动文件导入导出可作为后续补充，不是首版主要分享流程。

## 2. 当前代码能复用什么

| 已有实现 | 扩展方式 |
| --- | --- |
| `agent.Bot.Instructions`：职责文本 | 保留旧内容，增加结构化职责与边界，不让模型自动覆盖旧职责 |
| `BotVersion`：保存时记录快照，`version` 乐观锁 | 增加版本列表、差异预览、恢复入口 |
| `Connection.AllowedBots`：连接分配给指定 Bot | 在既有连接授权之上增加逐动作权限 |
| 工具执行前复查连接版本、授权、运行状态 | 加入当前 Bot 策略及策略版本复查 |
| 独立记忆、显式共享资料 | 配置页集中展示可读范围，导入副本从空数据开始 |
| 编辑、复制、暂停、归档 | 统一配置管理入口，明确归档与永久删除 |

代码依据：`backend/internal/agent/service.go`、`backend/internal/connectors/runtime.go`、`frontend/src/components/BotEditor.tsx`、`frontend/src/pages/BotsPage.tsx`。

需要一并修正的现状：

- 新建 Bot 时后端 `SaveBot` 强制开启全员协作，覆盖了调用方传入的限制。导入、复制路径必须能明确关闭协作，不能只修改前端开关。
- 界面的「删除 Bot」当前实际调用归档。应将普通入口改为「归档」，保留恢复路径；永久删除另设明确入口。
- 单聊、任务和群聊分别拼接职责提示词。新规则需要统一组装，避免只在某一入口生效。
- 当前群聊有独立的成员选择与讨论逻辑。第一版继续保持群聊只做讨论；协作执行的权限不能因为某个 Bot 被拉进群而扩大。
- 桌面端尚未集成 deep-link 和 single-instance 插件，需要新增协议注册、冷启动参数处理与已运行实例接收链接的流程。
- 现有本地 API 面向回环地址与单一所有者，不能直接暴露到公网作为模板服务。模板托管应有独立的认证与访问边界。

## 3. 边界写在哪里

入口保持可发现：侧栏 Bot 菜单 →「配置 Bot」，以及设置 →「我的 Bot」→「配置」。配置界面分为四块。

| 配置区域 | 用户填写或管理的内容 | 例子 |
| --- | --- | --- |
| 职责与边界 | 角色目标、负责事项、不处理的事项、工作方式、输出标准 | 视频助手负责选题和分镜；不代发邮件；先给脚本再生成视频 |
| 工具与数据 | 本机连接、逐动作权限、独立记忆、共享资料、协作对象 | 可查询视频规格；付费生成须确认；邮箱禁用 |
| 版本记录 | 查看变更、恢复某个历史版本 | 恢复昨天的职责定义 |
| 模板与分享 | 创建模板、预览发布内容、复制链接、发布新版、停用链接、查看导入来源 | 创建「短视频助手」模板并分享链接 |

保留当前「创建后再定义职责」路径，但把结果展示为可核对的正式配置。用户也可在创建时直接展开填写。AI 的「完善职责」只生成草稿，经用户保存才修改长期定义；日常聊天、工具返回内容和其他 Bot 的发言不能自行更改长期规则或授权。

自然语言规则决定模型应如何回答，但不能保证模型永远不违反语义限制。实际资源访问由后端权限强制执行。例如「不能发送邮件」应同时体现为发邮件动作被禁用；不能只写进提示词。

## 4. 权限如何执行

每项动作提供「禁用」「每次确认」「允许」三种状态。其中「允许」仍受产品固定规则约束，不能关闭已有的发邮件、付费生成及 MCP 调用等确认要求。具体动作按现有工具清单展示，不提供尚未实现的能力。

有效权限取以下约束的交集：产品规则、当前 Bot 策略、当前连接授权、本次任务授权。任何一层禁止，调用都不能执行；所需确认取各层最严格要求。

实现要求：

1. 工具目录只向模型提供有效授权的动作，执行前再次检查最新策略。内置 `workspace_create/list/read` 也纳入策略，不能成为绕过限制的入口。
2. 导入模板中的能力要求只供预览，不能自动绑定本机连接或授予权限。接收者在本机主动选择连接与动作后才可调用。
3. 撤销权限后，尚未执行的动作和待批准动作立即受新策略约束；旧批准不能跨策略版本沿用。已经提交给外部服务的动作不能假称被撤回。
4. 角色说明采用任务启动时的版本快照；新消息、新任务使用新版本。权限检查始终使用当前版本。策略撤销与最后提交之间应有同步边界，避免检查后又使用旧权限执行。
5. 委派不能用来绕过发起 Bot 的限制。若任务允许协作，执行动作还需满足该任务的授权范围和执行 Bot 的授权；其他 Bot 的私人记忆不会因为协作而自动公开。
6. 策略默认拒绝未知动作。未能识别的导入能力、已移除的工具和新增 MCP 工具均需用户重新确认。

职责与规则存于本地 SQLite，并包含在版本快照中；具体连接凭据仍由既有凭据库管理。规则不会写入普通长期记忆来充当唯一依据。

## 5. 怎么改、怎么删

| 操作 | 行为 |
| --- | --- |
| 修改职责、工作方式 | 编辑后保存，产生新版本；保存前可撤销 |
| 删除某一条规则 | 删除对应条目并保存，历史版本保留；删除文字规则不自动放开工具权限 |
| 关闭某项能力 | 在工具权限中改为禁用，后端约束后续执行 |
| 恢复旧版本 | 显示差异后保存为新的版本，不修改旧历史；不自动恢复已经撤销的连接授权 |
| 暂停 Bot | 停止接收新任务并阻止后续工具动作，已有数据保留 |
| 归档 Bot | 从常用列表隐藏，停止参与执行；可恢复，数据保留 |
| 永久删除 Bot | 仅在归档区域提供；展示影响并二次确认，停止相关运行后清理该 Bot 私有数据 |

永久删除不能简单级联删除所有关联记录：独立对话、私人记忆、专属产物和角色版本可随 Bot 清理；共享资料、其他 Bot 数据和共同群聊历史不随之删除。解除共享资料、连接及群成员中的该 Bot 引用；共同任务中保留必要的参与者占位与审计记录，不让其他参与者的历史失效。文件清理失败要记录并可重试。默认 Soren 继续沿用当前不可删除的限制。

## 6. 创建模板与链接导入体验

作者流程：「我的 Bot」顶部、Bot 菜单或配置页 →「创建 Bot 模板」→ 编辑模板名称、简介 → 预览完整的可分享配置与所需能力 → 确认发布 → 显示头像、名称、链接卡片 → 复制链接。创建模板时固定本次配置快照，后续编辑原 Bot 不自动改变已发布内容。

接收者流程：打开 HTTPS 链接 → 网页显示头像、名称、链接卡片并尝试唤起应用（浏览器可能要求允许或点击打开按钮）→ 应用获取并校验同一版本 → 自动显示同款卡片 → 点击「导入到我的 Soren」→ 按需在配置中改名、选择模型与连接。

链接示例仅表示待实现的路由，并非已部署地址：

- 分享链接：`https://<模板域名>/t/<templateId>/v/<revision>`。
- 唤起应用：`soren://templates/import?id=<templateId>&revision=<revision>`。

分享链接使用普通 HTTPS，方便发送、在浏览器查看和展示安装入口。自定义协议只负责把模板 ID 与版本交给 Soren，不在 URL 中塞入整份配置、凭据或任意下载地址。未安装 Soren 时，页面提供安装说明；安装后可再次点击链接。应用内另提供「粘贴模板链接」作为唤起失败时的入口，同样进入预览确认流程。

导入卡片默认只展示头像、名称、分享链接和导入按钮。重复导入时额外提示会创建新副本。发布者仍需在发布前预览完整配置，接收者导入后可在「配置 Bot」中查看与修改职责；工具权限默认关闭。

网页和应用必须展示同一不可变版本。首版不自动更新已导入 Bot。后续若增加更新功能，采用差异预览与手动合并，防止覆盖接收者自己的修改。

模板管理入口：配置 Bot →「模板与分享」，并在「我的模板」集中查看已发布模板，避免删除原 Bot 后丢失管理入口。

| 操作 | 行为 |
| --- | --- |
| 复制模板链接 | 复制指定版本的 HTTPS 链接 |
| 发布新版 | 再次预览并确认，生成新的不可变版本与链接；旧链接仍指向旧版本 |
| 停用链接 | 服务拒绝该模板或指定版本的后续读取；明确展示停用范围，可重新启用 |
| 删除已发布模板 | 删除服务端模板内容并停止后续下载；不删除作者本地 Bot 或接收者副本 |
| 删除本地 Bot | 不隐式删除已发布模板；删除时说明仍有模板在分享，并提供单独停用入口 |

已下载的配置无法通过停用链接收回。产品文案不承诺远程删除接收者副本，也不将模板版本回退等同于撤回。

## 7. 模板服务、认证与桌面入口

需要一个独立的轻量模板服务、存储和预览页。模板服务可以是小型服务或托管函数，保存模板所有者、发布状态及版本内容；不承载 Bot 推理，不接收聊天记录或模型密钥。不得通过公开桌面本地 API 实现分享。

首版建议采用「知道链接即可查看和导入」，不做公开搜索或市场；模板 ID 使用不可预测的随机标识。该模式不等于组织内保密访问。如果模板只能在公司内使用，必须改为受限模板，网页与模板内容 API 均验证登录和组织权限，不能只保护预览页。

发布、发布新版、停用和删除必须验证发布者身份及模板所有权。可复用公司 IdP，但需要补齐真实 OAuth/OIDC 登录、回调校验和服务端会话或令牌验证；仅从客户端提交作者 ID、OAuth 参数或显示名称不构成认证。认证方案还须确认文档所支持的身份校验方式，不预设存在 JWKS 或令牌 introspection 接口。发布者会话和 IdP 密钥不得放进模板或分享链接。

建议服务接口：

| 接口职责 | 访问规则 |
| --- | --- |
| 创建模板、发布版本 | 已登录发布者；创建时记录服务端确认的所有者 |
| 列出我的模板、停用、启用、删除 | 已登录且拥有对应模板 |
| 读取模板介绍与指定版本 | 根据模板访问模式检查状态及权限；停用后拒绝读取 |
| HTTPS 预览页 | 展示指定版本，转义自由文本，禁止执行模板中的 HTML 或脚本 |

发布和导入应允许安全重试，通过幂等请求避免重复创建。服务端也校验白名单、文本长度和大小上限，并限制请求频率。停用时同步清理受控缓存，内容响应避免长期公共缓存；对已经分发出去的副本不承诺撤回。

桌面入口要求：

1. 注册 `soren` 协议；处理应用未运行时的冷启动、已运行时向现有实例派发，并统一去重。收链接本身不创建 Bot、不授予工具权限。
2. 严格验证协议、路由、模板 ID 和版本，只从产品配置的受信模板服务获取固定路径；不接受链接指定任意抓取地址，不跟随跳转到未允许的域名。
3. 获取过程设定超时、响应大小与格式限制。导入确认绑定预览过的版本和内容摘要，确认阶段重新验证，防止预览内容和实际入库内容不一致。
4. 离线、模板已停用、版本不支持、服务不可达时显示明确原因，允许重试或取消；不写入半成品 Bot。协议处理覆盖打包后的 macOS，并按支持平台验证 Windows/Linux。
5. 如启用组织内访问，桌面下载也走相同认证；打开深链接本身不证明访问者已登录。

部署前需要确定模板域名、服务部署位置，以及「持链接访问」或「组织内访问」模式。实现中可先用本地模板服务验证全链路，再部署测试环境；没有可访问的服务地址时，不能声称链接已可跨电脑分享。

## 8. 配置格式与本地实现建议

采用 UTF-8 JSON 模板，首版不使用压缩包或可执行扩展。建议大小上限 256 KB，结构与文本长度均校验。未来可复用同一结构提供 `.soren-bot.json` 文件导入导出。

| 字段 | 作用 |
| --- | --- |
| `format`、`schemaVersion` | 标识 Soren Bot 模板及格式版本；不支持的版本明确报错 |
| `name`、`description`、`avatar` | 名称、简介、内置头像标识；未知头像使用默认头像 |
| `definition` | 职责、工作方式、输出标准、自然语言边界 |
| `policyTemplate` | 禁用动作、确认要求、记忆偏好、协作默认值；不包含本机实际授权 |
| `requiredCapabilities` | 稳定的能力名称与说明，不能使用本机连接 UUID 或临时工具编号 |
| `packageVersion` | 模板配置的内容版本，与格式版本区分 |
| `attribution` | 可选文字署名，不视为经服务验证的发布者身份 |

服务另行记录 `templateId`、不可变 `revision`、服务端发布时间、所有者、内容摘要和发布状态。已登录发布者来自服务验证的身份；配置中的自由署名与发布者分开展示。内容摘要用于一致性和去重，不代表内容安全或数字签名。

创建模板使用显式字段白名单，不能直接序列化整个 Bot 数据库对象。排除 API Key、OAuth 密钥、令牌、连接账号、本地路径、模型服务地址、对话、记忆、共享资料正文和运行记录。模型首版继承接收者的默认配置。

自由文本职责也可能被用户手动写入秘密或内部资料，因此发布前必须展示完整文本预览；白名单只能保证不自动带出系统存储的凭据，不能宣称文本一定不含敏感内容。

模板导入先校验再预览，用户确认后才落库。不执行模板内脚本、不自动访问正文中的 URL、不安装工具。模板中的工具说明也不能作为获得权限的依据。

建议复用或新增：

- `agent.Bot` 与 `BotVersion`：扩展角色定义；旧 `instructions` 原样迁移，已有 Bot 保留现有有效权限，迁移不扩大授权。
- `BotPolicy`：结构化动作策略、版本与数据范围。连接权限以现有 `Connection.AllowedBots` 为入口，避免出现两个互不关联的授权来源。
- 统一角色提示词组装器：供单聊、任务、群聊调用。
- 版本列表、差异与恢复接口；更新保持现有版本冲突检查。
- 创建模板预览、发布、读取版本、导入预览与导入确认接口；确认阶段重新校验，使用请求标识防止重复点击创建两份。
- Tauri 协议注册与单实例处理；前端统一消费待导入事件，等应用就绪再展示预览，重复启动不重复导入。
- 本地保存来源服务、模板 ID、版本、内容摘要与导入时间，供重复导入提示和后续手动更新使用；来源信息不授予权限。

按三个可独立验收的阶段实施，建议拆成多个提交或 PR：

1. **职责与边界管理**：扩展配置、规则编辑与删除、统一运行时策略、版本查看与恢复、明确暂停/归档/永久删除、修正新建及复制时强制全员协作的问题。
2. **创建与管理模板**：定义配置白名单和不可变版本、补齐发布者认证与所有权检查、建设轻量模板服务和预览页、实现发布/复制链接/发布新版/停用/删除。
3. **链接导入桌面端**：协议注册、冷启动及已运行实例接收、粘贴链接入口、下载校验与预览、创建独立副本、本机能力重新绑定及来源提示，完成跨电脑联调。

本次包含支持模板发布所必需的认证与托管，具体登录入口随访问模式确定；不扩展为完整的多用户云端 Bot 运行系统。公共网页聊天、Bot 市场、自动更新副本和文件导入导出补充入口不作为首版交付条件。第一版完成并部署后，两台装有 Soren 的电脑之间即可通过 HTTPS 模板链接分享 Bot。

验收标准：

- 能创建、编辑、删除单条职责规则，重启后保留；版本冲突不会覆盖新配置，恢复产生新版本。
- 被禁用动作在目录和执行阶段都不可用；待批准操作在授权撤销后不能执行；通过协作不能绕过任务权限。
- 单聊、任务、群聊使用同一份角色定义；规则不会只在配置页显示而未传给运行时。
- 归档可恢复；永久删除不会误删共享资料或其他 Bot 数据，活跃任务与群成员引用被正确处理。
- 作者可创建模板、复制链接、发布新版、停用和删除；非所有者不能管理，未登录不能发布。
- 网页预览与应用导入绑定相同的不可变版本；旧链接不会因原 Bot 编辑或发布新版而悄悄改变。
- 发布再导入保持可分享配置一致；模板不自动包含系统凭据、私人历史、实际连接授权或本地路径。
- 导入使用新 ID、空的对话与记忆、关闭的协作和未授权的外部连接；同名不覆盖，重复提交不重复创建。
- 冷启动、已运行实例及粘贴链接均可进入预览；打开链接不自动导入，取消不写数据库。
- 损坏、超大、未知版本及非法深链接无法触发自动行为；不能通过链接参数抓取任意地址或执行配置文本。
- 停用后服务拒绝后续读取；已导入副本仍可使用。组织内模式下，未获授权者不能通过内容 API 绕过网页登录。
- 接收者能使用自己的模型对话，授权自己的工具后完成实际任务；未配置的能力明确显示待连接。
- 在两台电脑上完成发布、打开网页、唤起桌面端和确认导入；没有安装应用、离线与模板失效时有可理解的提示。
