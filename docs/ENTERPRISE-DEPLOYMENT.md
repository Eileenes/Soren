# 企业部署基础版

本版交付“个人免登录 + 企业服务器连接”：管理员运行 Go 企业服务和 PostgreSQL；员工在桌面端输入公司服务地址，通过公司 OAuth 登录，确认账号后进入各自的 Bot、聊天、记忆、任务和连接器空间。

这是用于内部试点的单实例版本，尚未进行 1200 人容量验收。任务执行仍在企业 Go 进程内，状态持久化到数据库；重启后未完成任务收敛为暂停／结果待核实，按已有规则恢复，不自动重发外部操作。独立 Worker、多实例持久调度、部门配额、完整管理控制台和跨员工 Bot 服务目录属于后续阶段。

## 1. 部署组成与隔离

- `backend/cmd/enterprise` 是独立入口，不修改桌面本地 API 的 loopback 访问边界。
- PostgreSQL 保存公司成员与登录会话；每位成员拥有独立 schema、固定 search_path 的连接池、文件目录和运行时。客户端无法指定或切换 schema。相同默认 Bot ID 在不同空间中互不关联。
- 首次登录建立成员；第一次访问业务接口时初始化默认 Bot 和空间数据。现有本地数据库不会自动迁移或上传。
- 连接器凭据使用 AES-GCM 加密，附加认证数据绑定空间和凭据 ID。主密钥由部署环境提供，不能随数据库备份公开。
- 桌面内置 Go 服务充当公司 API 代理；公司会话令牌在本机系统凭据库中，前端只接收非敏感空间信息。请求不转发客户端提供的身份或授权头，不跟随跨地址重定向。
- 服务器使用专用数据库，数据库账号需要创建 schema 的权限。隔离防止正常 API 跨员工访问，不意味着数据库管理员无法读取业务数据，也不等于企业服务器端到端不可解密。

企业服务通过 PostgreSQL advisory lock 限制为一个实例。不要绕过该限制扩多副本：现有运行时的启动恢复会修改任务状态，必须先完成分布式任务租约与恢复设计。

## 2. 公司身份服务要求

向 IdP 管理员申请一个服务端 OAuth 应用，回调为：

```text
https://你的域名/auth/callback
```

需要确认：授权码流程、PKCE S256、Token 端点、Bearer UserInfo 端点、稳定且不可变的用户 ID 字段、客户端认证方式。实现支持 `client_secret_basic` 和 `client_secret_post`；公司 Client Secret 只配置在服务器。登录使用一次性 state、浏览器绑定 Cookie、PKCE，以及短期桌面授权轮询凭据；令牌不进入浏览器回调 URL。

本版基于配置的可信 UserInfo 端点确认身份，没有将任意 ID Token 解码当成身份验证，也不假定公司 IdP 已支持 discovery/JWKS。默认用户标识字段为 `sub`；如果公司文档约定的是 `id`，设置 `ENTERPRISE_SUBJECT_CLAIM=id`。不能使用可变的用户名或邮箱作为主键。

试点通过 `ENTERPRISE_ALLOWED_SUBJECTS` 填写允许登录的用户稳定 ID。只有 IdP 应用本身已经限制为合法员工，才可显式填写 `*`。仅配置企业域名或邮箱后缀不能作为成员资格验证。

Soren 会话有效期为 8 小时，保存在系统凭据库，重启桌面后可恢复；过期后重新登录。此版本不保存公司 IdP refresh token，也未对接离职 webhook／SCIM。IdP 停用账号后，已签发的 Soren 会话仍可能有效至到期，管理员应同时用下述命令停用 Soren 成员；正式全员推广前接入自动停用联动。

## 3. Docker Compose 部署

准备域名、服务器、Docker Compose 和 IdP 应用。需要外网使用时，配置可达的 HTTPS 网关或公司 VPN／零信任接入。

在仓库根目录执行：

```sh
cp deploy/enterprise/.env.example deploy/enterprise/.env
```

本地生成两个独立值，分别填入 `.env` 的数据库密码和凭据主密钥：

```sh
openssl rand -hex 32
openssl rand -base64 32
```

补齐域名、公司名称、OAuth 端点与应用凭据、允许员工 ID、模型名称和模型 Key。`.env` 不提交 Git。密钥仅留在管理员的安全存储／部署环境，普通员工不填写这些字段。使用云模型 API 时，应用服务器不需要 GPU。

```sh
docker compose --project-directory deploy/enterprise up -d --build
curl https://你的域名/healthz
curl https://你的域名/.well-known/soren
```

第一个接口检查数据库连通；第二个接口返回公司名称、协议版本和服务能力。它们不代表 OAuth、模型和业务已全部验收。

Compose 包含 PostgreSQL、企业应用和 Caddy。只有 Caddy 暴露 80/443，应用与数据库使用内部网络；数据库密码在连接串中使用，因此示例要求十六进制随机密码。企业文件位于 `enterprise_data` 卷，业务数据库位于 `enterprise_db` 卷。若复用公司 PostgreSQL，配置独立数据库及账号，并按数据库要求启用 TLS。

服务器已有网关时，复用现有网关转发到企业服务，避免多个服务争抢 80/443；TLS、网络准入和请求体限制保持一致。Go 单实例的进程内模型并发默认为 8，可通过 `ENTERPRISE_MODEL_CONCURRENCY` 调整，每个空间沿用现有任务限制；这不是 1200 人吞吐承诺。

## 4. 员工怎么使用

1. 安装包含此功能的新桌面版本。首次引导或窗口顶部“个人空间”、设置“使用空间”都可打开入口。
2. 填写管理员提供的 HTTPS 根地址，点击“识别服务器”。
3. 确认显示的公司名称，点击“使用公司账号登录”，在系统浏览器完成授权。
4. 回到客户端核对登录账号并进入公司空间。员工无需提供 OAuth 应用凭据。
5. 使用自己的默认 Bot；在应用连接中为自己的 Bot 配置业务平台授权。模型由管理员统一提供。
6. 在“使用空间”退出公司，回到免登录的个人本地空间。退出不会删除公司数据，也不会将其复制到本地。

服务器离线或登录过期时，客户端保留公司上下文并明确显示错误，不自动回落到个人模式。数据库或网络短暂故障不会被当成登录过期，恢复服务后可重试原会话。账号确认须在登录请求的 5 分钟有效期内完成，超时后可重新发起登录。切换空间后界面与内存中的会话状态重新初始化，选中 Bot／群聊的偏好按服务器和用户隔离。离线退出会清除本机连接；若无法通知服务端撤销，会话在到期后失效，界面会提示。

此版本企业连接器支持已实现的 Token／API Key 方式（Notion、MCP／OctoBus、百智云工具等），权限取决于员工实际授权。Gmail OAuth、飞书／钉钉消息渠道、模板发布及手机企业登录尚未接入公司模式，不能用个人模式的配对码作为向同事共享 Bot 的凭据。

## 5. 成员管理

列出已登录的成员，获取其内部 ID：

```sh
docker compose --project-directory deploy/enterprise exec enterprise soren-enterprise users
docker compose --project-directory deploy/enterprise exec enterprise soren-enterprise disable USER_ID
docker compose --project-directory deploy/enterprise exec enterprise soren-enterprise enable USER_ID
```

停用阻止后续 API 访问；模型调用及任务工具调用前也会重新检查停用状态。已向外部平台提交的操作不能追回，正在发生的上游请求也不承诺立即取消。停用／启用均撤销已有会话，重新启用后需要重新登录。

## 6. 发布前验收与运维

- 两名真实员工分别登录：创建 Bot、发送聊天、保存记忆、提交任务；对方即使知道对象 ID，也不能读写。
- 用真实公司 IdP 验证 PKCE、UserInfo ID 字段、授权拒绝、过期、退出和停用。仓库模拟 IdP 测试不能替代真实对接。
- 真实连接器按各自权限调用，审批和撤销生效；模型 Key 和连接器令牌不出现在客户端响应、日志或普通数据备份中。
- 个人 → 公司 → 个人切换正确；重启桌面可以恢复公司会话；网络不可达时不发送到错误空间。
- 备份 PostgreSQL 的完整数据库（包含全部 workspace schema）、企业文件卷，以及独立保护的主密钥。升级前备份，恢复到测试环境验证；仅备份 public schema 会遗漏员工业务数据。
- 先选 20–50 人试点，观测 API 延迟、模型并发与限流、连接池、任务恢复、磁盘和模型费用。单机故障会中断服务，未实现高可用和持续性服务承诺。

后续再建设公司 Bot 目录、跨用户能力授权、部门权限与额度、IdP 停用同步、分布式执行和 1200 人容量验收。

## 7. 开发验证

本次本地验证覆盖：

- Go 全量竞态测试和 `go vet ./...`；企业 OAuth、双员工数据隔离、停用与退出、凭据加密，以及桌面代理保持令牌不进入前端。
- 使用临时 PostgreSQL 17 验证 schema 隔离、重复初始化、重开员工空间和数据保留；通过模拟 IdP 跑通桌面代理、浏览器授权、账号确认、聊天持久化与退出。
- 移除桌面旧 OAuth 配置功能并补充审查回归用例后，前端 156 项测试及生产构建通过，桌面 Rust 9 项测试通过；同时移除了仅针对旧配置功能的测试。浏览器使用模拟接口检查过登录确认、空间切换、退出与 720px 窗口布局。
- 回归测试覆盖数据库故障与恢复、服务异常时保留会话、离线退出的撤销结果、账号确认超时、轮询重试，以及本地服务延迟启动后的自动恢复。
- Docker 镜像构建、Compose 配置解析、容器启动与重启、健康检查、服务发现、成员列表命令，以及重复实例被数据库锁拒绝。

重复初始化测试发现并修复了旧 PostgreSQL 驱动在检查已有表时的参数编号错误，依赖调整为 `gorm.io/driver/postgres v1.5.11` 和 `gorm.io/gorm v1.25.10`。

复测 Go 集成链路时，为 `SOREN_TEST_POSTGRES_URL` 提供专用的临时 PostgreSQL 数据库，再在 `backend/` 执行 `go test -race ./...`。未设置该变量时会跳过真实 PostgreSQL 用例。测试会创建和删除测试 schema，不能指向已有业务数据库。

上述验证使用模拟身份服务和测试凭据。真实公司 IdP、实际模型及连接器权限、桌面系统凭据库和浏览器授权联调、签名安装包分发、HTTPS 域名上线及 1200 人负载测试仍需在部署环境完成。
